Classify every wrong prediction into one of these before deciding what to fix
(`AGENTS.md` §Error Analysis mandates the classification; this is the taxonomy):

```text
When performance is poor, do not immediately add another model.
First classify failures.
Useful categories:
```text
NAME_NOISE
ADDRESS_NOISE
MISSING_ADDRESS
MULTILINGUAL
TRANSLITERATION
COMMON_NAME
COMMON_ADDRESS
WRONG_RETRIEVAL
FALSE_POSITIVE
FALSE_NEGATIVE
SINGLETON_ERROR
MULTI_MATCH_ERROR
COUNTRY_SHIFT
```
Then identify:
```text
What failed?
Why did it fail?

## 61. Definition of Difficult Terms

When explaining technical concepts to the team, use simple language.

### Entity Resolution

Determining which records from different datasets refer to the same real-world entity.

Example:

```text
"ABC Pvt Ltd"
"ABC PRIVATE LIMITED"
"ABC PVT. LTD."
```

may represent the same business.

---

### Record Linkage

Another name for matching records that refer to the same real-world entity.

---

### Candidate

A possible match generated by the retrieval system.

---

### Candidate Generation

The process of finding a small set of possible matches instead of comparing every record against every other record.

---

### Blocking

A technique for reducing the number of comparisons.

Instead of:

```text
1 S1 record
→ millions of S2 records
```

we might retrieve:

```text
1 S1 record
→ 100 candidates
```

---

### Recall

How many of the true matches we successfully found.

High retrieval recall means:

> We did not accidentally throw away many true candidates.

---

### Precision

How many predicted matches are actually correct.

High precision means:

> When we say it matches, we are usually right.

---

### F0.5

A metric that combines precision and recall while giving more importance to precision.

For this challenge, false positives are therefore especially important.

---

### Hard Negative

A wrong candidate that looks very similar to the correct candidate.

Hard negatives are useful because they teach the model difficult distinctions.

---

### Feature

A numerical signal given to the model.

Example:

```text
name_similarity = 0.92
address_similarity = 0.71
country_same = 1
```

---

### Rarity / IDF

A measure of how uncommon a word/token is.

Rare terms usually provide more identifying information than common terms.

---

### Calibration

Making model probabilities better reflect actual confidence.

For example:

```text
0.90 probability
```

should ideally correspond to something close to:

```text
90% likelihood
```

over comparable predictions.

---

### Threshold

The cutoff used to decide whether a candidate should be accepted.

Example:

```text
probability >= 0.90
```

The exact threshold must be experimentally determined.

---

### Margin

The difference between the best candidate and the next-best candidate.

Example:

```text
Candidate A = 0.97
Candidate B = 0.40

margin = 0.57
```

Large margins can indicate clearer decisions, but margin alone is not proof of correctness.

---

### Entity-Level Evaluation

Evaluating the final set of matches for each S1 entity rather than treating every candidate pair independently.

This matters because one S1 entity can have:

```text
multiple correct matches
```

or:

```text
no correct matches
```

---

### Data Leakage

When information from validation/test data accidentally influences training or decision-making.

Leakage can make local scores look much better than real performance.

---

### Distribution Shift

When the test data is meaningfully different from training data.

Example:

```text
Training:
US + India

Test:
US + India + France
```

---

### ANN

Approximate Nearest Neighbor search.

A fast method for finding records that are approximately closest to a query in vector space without comparing against every vector.

---

### Embedding

A numerical vector representation of text.

Similar meanings can sometimes produce similar vectors even when the words differ.

---

### Reranker

A second-stage model that takes retrieved candidates and reorders them using more detailed information.

---

### Ablation

Removing one component to see how much it contributes.

Example:

```text
Model A = all features
Model B = all features except rarity
```

The difference tells us whether rarity actually helps.
